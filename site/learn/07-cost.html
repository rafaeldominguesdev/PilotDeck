chapter 07 of 08 · cost per card

Tokens are the fact, dollars are arithmetic

An agent knows how many tokens it burned. It usually does not know today's price. So the board keeps a price table per model and does the multiplication itself, and every figure on screen says where it came from.

01 · where the numbers come from

Usage arrives with the delivery

task_deliver carries a usage block: input tokens, output tokens, cache tokens, duration, turns, and optionally a cost. Exact numbers when the harness exposes them; otherwise an estimate marked estimated: true.

One number does not depend on agent goodwill at all: the server measures the duration itself, from claim to deliver. A card delivered by an agent that reports nothing still shows real time on it.

02 · the price table

Settings › Model prices

One row per model: input, output and cache price per million tokens. The table ships seeded with public list prices and each seeded row is stamped with the date those prices were read, so nobody has to guess how old a number is. Every value is editable, because your contract is not necessarily the list price.

Models the board has seen run but cannot price are offered right there, waiting for a number. An unpriced model is never invented: it is counted separately so a total cannot quietly pretend to be complete.

Cache column. It prices the tokens_cache counter of the usage contract and is seeded at the cache read rate, which is what a long agent session is mostly made of. If your provider bills you differently, that is the row to change.
03 · three labels

Every figure says where it came from

LabelMeaningTrust
computed The board multiplied the reported tokens by your price table. As good as the price you typed. This is the default whenever tokens exist.
agent reported The agent sent a dollar figure and the board had no price for that model. Depends on the CLI knowing current prices. Add the model to the table to upgrade it.
estimated Same as above, and the agent flagged its own numbers as a guess. Directional. Fine for a trend, wrong for a budget.

The labels travel everywhere the number does: the card footer, the totals, the per-card table, and the MCP response. A mixed total says so instead of borrowing the most flattering label.

04 · insights

The four questions the page answers

  • What did this project cost? Totals per project, with tokens and time next to the dollars.
  • What did this mission cost? The same, grouped by mission, which is how a feature-sized effort gets a price.
  • Which model is eating the budget? Grouped by model. Pair it with the next question before you react.
  • Which model gets reopened? The reopened rate per model: deliveries that a human sent back. A cheap model that is reopened half the time is not cheap.

Only finished attempts count, example cards stay out so demo data never inflates real cost, and a card nobody could price keeps a null instead of a fake zero. The honesty note above the totals tells you how many attempts were estimated and how many reported nothing.

05 · from an agent

The same numbers over MCP

insights_query runs the same loaders and the same aggregation the page runs, so an agent's answer and your screen cannot disagree. Group by project, mission, model or card, and narrow with since and until.

say this to your agent query insights grouped by model for the last two weeks, and tell me which model has the worst reopened rate

The price table is readable too, through harness_list. That is what lets an orchestrator reason about cost before it picks a harness, instead of discovering the bill afterwards.

06 · acting on it

Turn a number into a policy change

Cost data is only worth collecting if it moves a decision. The two moves that actually pay:

  • Downgrade what does not need judgment. Mechanical work on a top model is the most common leak. One policy line fixes it for every future card.
  • Upgrade what keeps coming back. A type with a high reopened rate is paying twice: once for the run, once for your review. The cheaper model was not cheaper.

Chapter checklist

  • Every model your team runs has a row in the price table
  • You know when the seeded prices were captured, and have updated the ones that changed
  • Cards show a cost labeled computed, agent reported or estimated
  • You can name the most expensive mission of the month
  • You have looked at the reopened rate per model, not just the cost
  • At least one policy line changed because of a number you saw
