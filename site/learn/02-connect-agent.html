chapter 02 of 08 · connect an agent

Six digits instead of a secret

The board speaks MCP over streamable HTTP with a bearer token. The safe way to hand that token to an agent is to never say it out loud: generate a one-time code, let the agent exchange it, and the real value goes straight into its config.

01 · why not paste the token

A token pasted in a chat is a token in a log

Anything you type into an agent conversation ends up somewhere: a transcript, a crash report, a screen recording, a livestream. A bearer token that reaches your board is worth exactly as much as the board itself. So the wizard offers a pairing code: six digits, valid once, expiring in ten minutes, useless to anyone who reads them after the exchange.

02 · pair

Generate the code, then tell your agent

In the onboarding wizard's third step, or later in Settings › MCP tokens, click the pairing-code button. The board shows six digits and an indicator that lights up the moment they are exchanged.

say this to your agent pair with my PilotDeck board at localhost:3000 with code 483920, store the token in your MCP config, and never print it

The agent posts the code to the public pairing endpoint and receives the real token. If your agent would rather be handed the command, this is the one it runs:

$ curl -sX POST http://localhost:3000/api/pair \ -H 'Content-Type: application/json' -d '{"code":"483920"}' # → {"token":"ocb_…","url":"/mcp"} single use · 10 minute TTL

The response carries the token and the MCP path. The agent stores it and connects to /mcp with an Authorization: Bearer header. The code is now dead.

03 · the classic path

When you are pasting into your own terminal

Generate a token in Settings › MCP tokens (it is shown in full exactly once) and copy the ready-made command. Use this path only when the text goes into a shell you control, not into a conversation.

$ claude mcp add --transport http pilotdeck http://localhost:3000/mcp \ --header "Authorization: Bearer ocb_your_token"

Codex, Gemini CLI and Overclock take the same URL and the same header; only the command that registers the server differs. The workspace is resolved from the token, so an agent never picks one.

One token per agent, per machine. They are revocable and the list shows when each was last used, so a laptop that leaves the team is one click, not a rotation.
04 · the manage flag

Give a worker token the smallest thing that works

Claiming and delivering cards is what a worker token is for. Rewriting the workspace configuration is not: a token that can move the harness policy can promote itself to a better model between two claims. So the configuration tools (harness_set, executors_update) sit behind a per-token manage flag that is off by default; without it they answer PERMISSION_DENIED and change nothing.

Tick it only for a token you trust to rewrite policy, usually an orchestrator you run yourself. Tokens that have it wear a manage badge in the list.

05 · first card

Now do not touch the board

Your instance was born with an example card. Ask for it in the terminal:

say this to your agent grab the next task from the board

The agent calls task_claim, the card slides to In progress with the executor's identity on it, and the agent receives a self-contained briefing: the contract, the harness, the mission context, and the branch convention. It needs no other source. When it finishes, it calls task_deliver and the card lands in Done · review with a summary, evidence, and the real cost.

06 · troubleshooting

Three things that go wrong

SymptomWhat to check
401 on every call The token was revoked, or the Authorization header was pasted incomplete. Generate a new one in Settings › MCP tokens.
The pairing indicator never lights Is the container up? Can the CLI reach the host? A code older than ten minutes is already expired: generate another one.
The agent talks about the wrong board PilotDeck is the task board, not the IDE that may be hosting the agent. The server ships that identity in its MCP instructions, but a confused agent gets clear if you name the tool: "use task_list on pilotdeck".

Chapter checklist

  • The agent is connected over MCP and no token was ever typed into a chat
  • The pairing indicator lit up, or the token command ran in your own terminal
  • Worker tokens do not carry the manage flag
  • "Grab the next task from the board" moved a card to In progress
  • The delivered card shows a summary, evidence and telemetry in Done · review
