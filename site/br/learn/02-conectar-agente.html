capítulo 02 de 08 · conecte um agente

Seis dígitos no lugar de um segredo

O board fala MCP sobre HTTP streamable com um token bearer. O jeito seguro de entregar esse token a um agente é nunca dizer o token em voz alta: gere um código de uso único, deixe o agente trocar, e o valor real vai direto para a configuração dele.

01 · por que não colar o token

Token colado num chat é token em log

Tudo o que você digita numa conversa com agente termina em algum lugar: transcrição, relatório de crash, gravação de tela, live. Um token bearer que alcança o seu board vale exatamente o que o board vale. Por isso o wizard oferece um código de pareamento: seis dígitos, válidos uma vez, que expiram em dez minutos e não servem para ninguém que os leia depois da troca.

02 · pareie

Gere o código e fale com o agente

No terceiro passo do wizard, ou depois em Configurações › Tokens MCP, clique no botão de código de pareamento. O board mostra seis dígitos e um indicador que acende no instante em que eles são trocados.

fale isso para o seu agente pareie com o meu board do PilotDeck em localhost:3000 com o código 483920, guarde o token na sua config de MCP e nunca imprima esse valor

O agente manda o código para o endpoint público de pareamento e recebe o token real. Se o seu agente preferir receber o comando pronto, é este:

$ curl -sX POST http://localhost:3000/api/pair \ -H 'Content-Type: application/json' -d '{"code":"483920"}' # → {"token":"ocb_…","url":"/mcp"} uso único · vale 10 minutos

A resposta traz o token e o caminho do MCP. O agente guarda e conecta em /mcp com o header Authorization: Bearer. O código já morreu.

03 · o caminho clássico

Quando você cola no seu próprio terminal

Gere um token em Configurações › Tokens MCP (ele aparece por inteiro uma única vez) e copie o comando pronto. Use este caminho só quando o texto vai para um shell que é seu, nunca para dentro de uma conversa.

$ claude mcp add --transport http pilotdeck http://localhost:3000/mcp \ --header "Authorization: Bearer ocb_seu_token"

Codex, Gemini CLI e Overclock usam a mesma URL e o mesmo header; só muda o comando que registra o servidor. O workspace é resolvido pelo token, então nenhum agente escolhe workspace.

Um token por agente, por máquina. São revogáveis e a lista mostra o último uso de cada um, então um notebook que sai do time é um clique, não uma rotação inteira.
04 · a flag de manage

Dê ao token de trabalho o menor poder que resolve

Pegar e entregar card é para isso que serve um token de trabalho. Reescrever a configuração do workspace não é: um token que muda a política de harness pode se promover para um modelo melhor entre dois claims. Por isso as ferramentas de configuração (harness_set, executors_update) ficam atrás de uma flag manage por token, desligada por padrão; sem ela, respondem PERMISSION_DENIED e não mudam nada.

Marque a flag só para um token em que você confia para reescrever política, normalmente um orquestrador que é seu. Tokens com ela ganham um selo manage na lista.

O agente chama task_claim, o card desliza para Em execução com a identidade do executor, e o agente recebe um briefing autocontido: o contrato, o harness, o contexto da missão e a convenção de branch. Ele não precisa de outra fonte. Ao terminar, chama task_deliver e o card cai em Feito · revisão com resumo, evidência e o custo real.

06 · quando dá errado

Três coisas que acontecem

SintomaO que checar
401 em toda chamada O token foi revogado, ou o header Authorization foi colado pela metade. Gere outro em Configurações › Tokens MCP.
O indicador de pareamento não acende O container está de pé? A CLI alcança o host? Um código com mais de dez minutos já expirou: gere outro.
O agente fala do board errado PilotDeck é o board de tarefas, não a IDE que talvez esteja hospedando o agente. O servidor manda essa identidade nas instruções de MCP, mas um agente confuso desencalha quando você nomeia a ferramenta: "use task_list no pilotdeck".

Checklist do capítulo

  • O agente está conectado via MCP e nenhum token foi digitado num chat
  • O indicador de pareamento acendeu, ou o comando com token rodou no seu próprio terminal
  • Os tokens de trabalho não carregam a flag manage
  • "Pega a próxima task do board" moveu um card para Em execução
  • O card entregue mostra resumo, evidência e telemetria em Feito · revisão
